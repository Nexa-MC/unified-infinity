## What the proposed run can and cannot establish

Only actual runtime records can establish two distinct game processes, loopback
socket ownership, nonce direction/counter/thread behavior, client disconnect,
server save and clean owned exits. Source/mock checks do not establish any of
those observations. Software graphics does not certify manual GUI behavior.

The rapid Unified lifecycle case previously exposed38 recipe errors and one
plugin null-level error. It remains open. Completed-reload success is a separate
condition and does not resolve that rapid case, all loader APIs or QSL/Forge
facade wire compatibility.

The Ubuntu runner image/package inventory and actual graphics/memory capacity
remain runtime observations. Cold-download latency may exhaust the fixed work
budget; that must fail with cleanup and evidence rather than extend the job.
No secrets, caches, uploaded binary artifacts, larger runners or paid-service
enablement are part of this proposal.
