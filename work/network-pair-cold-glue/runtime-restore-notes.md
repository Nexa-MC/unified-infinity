# Official runtime restoration source

`runtime_restore.py` prepares a fresh consumer-local text plan. It does not run downloads, Java, Gradle, installers, games, CI, Git, or browser automation. The only executed checks were Python source/metadata checks and three source-only behavioral tests.

The concrete API is `prepare(repo_root, consumer_root)`. It places official runtime inputs under `consumer_root/work/api1`, preserving the existing project topology. `build.gradle` and `settings.gradle` are copied byte-for-byte from the already verified client exporter. Its exported game recipe retains 1280 MiB/two CPUs and `forgeclientdev`. All installer/build JVMs inherit the separate 512 MiB/one-CPU environment; Gradle is serial, one worker, strictly verified and offline. The task graph permits only the known preparation tasks and rejects every game task.

The returned plan has explicit Java/Gradle/cache/Maven/assets paths, five serial recipes, and separate `restore`, `verify_inputs`, and `verify` Python hooks. The five recipes are toolchain extraction, official client installation, official native server installation, `prepareClientLaunch -x downloadAssets`, and the relocated existing client sealer. The outer driver owns execution admission and process supervision. The frozen nonce diagnostic bootstrap, workflows and previous proposals are not changed or imported.

The effective restoration lock composes the unchanged 360-record compile input closure with existing immutable public/FML/Minecraft/asset locks and 73 supplemental records. Seventy supplemental records come from the exact official installer’s `install_profile.json`, checked against its SHA-1/size and existing SHA-256 bytes. Three are the captured official DevLaunch 1.0.2 JAR, POM and module metadata; all three already have matching SHA-256 values in the unchanged original strict verification XML, and the module independently declares the JAR digest and has no runtime dependency edges. Exact NeoForge repository URLs follow the same captured official repository layout as the existing compile lock. These URLs were not fetched during this task.

After deduplication there are 4,270 public download records totaling 1,482,465,250 bytes. The list includes the 3,888 unique Minecraft asset objects and index 17. Aliases are copied only after byte/hash validation; this avoids duplicate downloads. The original 360 compile records remain embedded unchanged in the effective lock for reconciliation. Public sizes absent from the old FML lock are fixed in the new source lock after verifying each original SHA-256 locally.

Expected output checks are distinct from downloads: four installer-generated FML inputs; the genuine two binary-only ModDev outputs; the original exporter’s additional `minecraft-1.21.1-clean.jar`; and all 95 native server closure files, including the genuine installer-extracted `unix_args.txt`. No generated Minecraft artifact is represented as a downloadable Maven release. The actual client export must reproduce the 95 known classpath identities under the consumer root, and its existing official sealer records the genuine argument files and native resources.

The current static reconciliation reports `missingOfficialInputs: []`. This means no unresolved URL/hash/size records remain for these known closures. It is not a cold execution pass. Cold installer preparation, offline client dependency resolution, official output regeneration, client export/sealing, and pair assembly have not been run here. Installer and NFRT may have their own network behavior; Gradle `--offline` is not OS-level network isolation. No namespace or security-setting change is required or proposed; the receipt simply does not claim OS-level network isolation. This module checks the complete public input closure before/after and rejects unexpected Maven/NFRT input files.

The outer driver still supplies the unchanged own nonce probe build and real 46-check receipt, build receipts for the source tuple, shared candidate-assembly input routing, and final pair assembly. The client sealer expects the source materializer’s assembler at `consumer_root/work/api1/source-workspace/fml-unified/tools/assemble_installation.py`. Pair/game execution remains outside this restoration module.

Source checks:

- `PYTHONDONTWRITEBYTECODE=1 python -m unittest discover -s work/network-pair-cold-glue -p test_runtime_restore.py -v` passed all three checks
- Tests block process/network entry points, preserve all 360 records, inspect fresh source staging, require byte-identical exporter source, reject canonical/traversal destinations, reject reused preparation roots and detect mutated consumer build source

The plan additionally exposes `nonceCompileInputs.originalLock`, `seedRoot`, `mavenRoot`, `nfrtArtifactsRoot`, and a full 360-row original-path → consumer-path map. The original nonce dependency lock is staged byte-for-byte. The outer driver can build its new reviewed derivative against these shared seeds without importing the old branch-guarded bootstrap.
