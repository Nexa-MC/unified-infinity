Status: **unmerged, production admission unchanged, real loader/game unverified**.

This is source/contract work based on the immutable API1 source snapshot (736 entries, SHA-256 `c797a562f4a4b14eae619c89aaca75223f5315c599a9cd79f84d49f7a4af7e70`). The nine necessary owner/context/event/transformer sources are materialized in `base/`, with byte identity in `base-manifest.json`. Canonical API1 sources, built artifacts, profiles, ledgers and Git were not changed.

`src/main/java/` contains the actual proposal. `patches/c1-unmerged.patch` is a reviewable patch against the canonical paths; **it has not been applied there**. `proposed-source-changes.json` lists every proposed target and source hash. A full assembled candidate build, integration review and authorized game acceptance are still required before any config API admission.

## Implementation

- Relocated Forge 52.1.0 `ForgeConfigSpec` and `IConfigSpec` retain the official validation/default/comment/range/list/cache semantics. The full source implementation is retained as an implementation detail; the proposed external slice is only the explicit fixture symbols. Unsupported methods do not gain admission by existing here.
- The spec's only semantic extensions bind save and mutation callbacks to the existing native owner. Autosave executes raw mutation, owner save, then the successful cache commit under the native per-mod lock. A paired failure injection against pinned Forge source confirmed the original WritingException family, old cached value, mutated raw data and unchanged disk; the initial candidate cache mismatch is preserved as failed evidence and corrected in the final source. The official production/development pre-load behavior and all-value reload cache invalidation are preserved.
- `ForgeConfigSpecAdapter` composes the Forge spec into native `IConfigSpec`; the int-returning Forge correction method and void-returning native method stay on different classes. Read-only native views are recursively copied before the Forge dry-run check, avoiding unsafe mutable casts. No custom implementation of sealed `ILoadedConfig` exists.
- `ForgeModConfig` supplies one stable facade per native record and returns the original Forge spec. Registration accepts only exact built-in specs and COMMON, skips empty specs, and uses the native tracker exactly once. The existing injected context receives the two bounded overloads without another context or ThreadLocal.
- Native `ConfigRegistrationPolicy` is a neutral internal hook. Native defaults preserve recovery, backup, save-event and dispatch behavior. The Forge adapter opts into strict read failure, no initial correction backup, created-template validation, final initial save, and no synthetic save-time Reloading. Loading/Reloading are selected at the owner's dispatch point. No second bus/tracker/path/watch/file engine is added.

Only five existing sources change: native ConfigTracker, LoadedConfig, ModConfig, the existing Forge loading context, and Forge52Symbols. Native watcher, interface, event and tracker-view sources are unchanged. The new owner policy and Forge facade files are additions.

## Scope and remaining integration risks

C1 targets injected-context COMMON registration; the boolean/ranged-int/worldRestart-int/string/list builder slice; Loading/Reloading getters; disk load/reload/correction; autosave/save/fresh reopen. SERVER, CLIENT, legacy context, raw data, direct config construction, custom specs, tracker APIs, and public unload/sync remain unsupported.

The deterministic harness exercises actual patched native owner source and real NightConfig 3.8.3 disk IO. Its test stand-ins are loader bootstrap paths/environment, the container's typed event sink, and FileWatcher scheduling. The owner still installs/removes the callback; the stand-in invokes it explicitly. This proves neither actual OS watcher scheduling nor the real mod bus/error-wrapper path, classloader/module integration, Loading-before-common-setup timing or a game launch. Both official spec sources used as controls remain byte-identical extracts.

A separate deeper harness passed 21 assertions using the actual frozen native ModContainer.final acceptEvent, bus 8.0.5, and real NightConfig 3.8.3 FileWatcher. It observed an external atomic-write transition and an autosave transition through OS notifications; CodeSource assertions exclude the deterministic watcher stub. It waits for the asynchronous owner watch-registration queue to acknowledge readiness before writing. The initial unacknowledged test timed out, and that failure is preserved. The unmodified frozen native owner reproduced the same missed first write without acknowledgement and succeeded with it. This identifies an inherited watcher-readiness race; no production behavior was changed to conceal it. It remains relevant to immediate post-load edits during later real-host integration. Exact OS event counts, a real injected mod constructor, Loading-before-common-setup ordering, Minecraft and full module/classloader integration remain unverified.

The exact allowlist inventory is a **proposal** under `../../four-loader/forge-config-c1-tests/boundary/`, implemented and tested only in the isolated copy of the real ASM transformer. Its candidate ABI fingerprint is forge52-mojmap-slice-4-common-config-c1-unmerged. All 29 proposed additions were emitted by the independently official-Forge compiled input; the real candidate transformer accepted both positive classes and rejected 22 negative classes. Canonical production transformation, full-runtime linking and assembled cache integration remain separate gates. The paired failure oracle uses the exact pinned Forge source and the installed NightConfig 3.8.3 dependency, matching the host version under test. COMMON disposal in the focused harness silently clears/detaches state; no Forge Unloading contract is claimed. Native atomic writing is retained. Spec subclass/custom implementation support is deliberately rejected.
